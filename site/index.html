How it works

One verified PR per issue, never filler.

ScoutFinds unclaimed bugs, reads each repo's AI policy, flags DCO and CLA.
WorkerRe-checks the issue, reproduces the bug, writes a failing test and the smallest fix.
VerifyThe coordinator confirms the PR exists and reads CI and review feedback.
ReplyA watcher drafts replies to maintainers. A reply is read, then posted.
ScoreRe-checked every five hours. Merged +1, rejected −1.

Checked and skipped

Most of the work is deciding not to open a PR.

Projects that restrict AI-written PRs not submitted
  • scikit-image: a real bug in max_tree, but the policy bans AI-written code and PR text.
  • django-modern-rest: forbids autonomous agent PRs and requires human-written PR text.
  • networkx, thanos, OpenTelemetry: AI-generated contributions banned or restricted.
Issues that were already claimed skipped
  • sktime: 47 open bugs, every real one already had a PR or a claim.
  • Open Food Facts: three issues each had a contributor claim and a claim-first rule.
  • Data and ML libraries: bugs had PRs within days, many from other AI-assisted contributors.
Needs the owner personally held
  • DCO sign-off requires the contributor's legal name, and a CLA needs their own signature.
  • opendal and gravitino want a human to review the PR text before it is submitted.
  • kargo and openinference need a DCO name and a CLA respectively.
Clean after full test runs no bug
  • humanize, tabulate, click, jinja and more-itertools pass their suites on Python 3.14.
  • sktime metrics, splitters and datatypes match reference formulas and invariants.
